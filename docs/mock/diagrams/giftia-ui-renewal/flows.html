チームレビュー用。正本は 要求.md・仕様.md・設計.md・キックオフ記録（#22〜#32）。文書にある流れだけを描き、文書に無い所は紫の破線＋「仕様に書かれていません」で示します。ID は小さく付けています（SP＝仕様、D＝設計、AC＝受入基準）。第2弾（実装③。開発 11/15〜11/18）で足した所は、薄紫の地・太い紫の枠・札「実装③」で区別します（第2弾の対象版は 5 文書 8243007、この図は main 6764510 の文書から描きました）。説明と ID は「くわしく」、失敗は「失敗したとき」を押すと開きます。

① 顧客視点

選ぶ→リンクを作る→仲間が開く→購入へ

Aさんが仲間に候補を送って決める流れ。

Aさん（Exhibit 2）: 同僚3人で送別品（1,500円ずつ＝総額4,500円）。30分で10商品以上見て一度閉じ、夜に3商品へ絞ってLINEに送り、2人の賛成で購入。R-01 の体験: (1) 1回の訪問で、仲間に見せられる候補を3つほどに絞りきれる (2) 仲間がひと目で「それならいい」と言える理由つきで送れる。

1価格帯（任意）を選び、シーン「送別」のタイルを押す

くわしく
