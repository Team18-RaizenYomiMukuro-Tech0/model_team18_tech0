① 顧客視点：Aさんが仲間に候補を送って決める

Aさん（Exhibit 2）: 同僚3人で送別品（1,500円ずつ＝総額4,500円）。30分で10商品以上見て一度閉じ、夜に3商品へ絞ってLINEに送り、2人の賛成で購入。R-01 の体験: (1) 1回の訪問で、仲間に見せられる候補を3つほどに絞りきれる (2) 仲間がひと目で「それならいい」と言える理由つきで送れる。

1価格帯（任意）を選び、シーン「送別」のタイルを押す 例: 3,000〜4,999円。価格帯は「〜2,999円／3,000〜4,999円／5,000円〜」の3ボタンから1つ（任意。同じボタンで解除）。シーンは3つのタイルから1つ。押した時点で候補が出る（「候補を出す」ボタンは無い）。 SP-01 ／ D-08 ／ F-01 ／ 体験(1)
↓
2候補と理由を見る（上位10件・順位順） 各候補に、事実をつなげた自然な文の理由。例「職場の送別で48回選ばれていて、評価も4.6（120件）と高めです。2日で届き、ラッピングもできます。」 SP-01〜03 ／ D-01〜D-04 ／ F-01, F-01a, F-02 ／ 体験(2)
0件価格帯ありは「条件に合う商品がありません。価格帯を変えてみてください」、価格帯なしは「この条件に合う商品がありません。シーンを変えてみてください」→ 変えて出し直す。SP-01
失敗・10秒で打ち切り「失敗しました。もう一度お試しください」と再試行ボタン。SP-01 ／ 500

0件選択「共有リンクを作る」ボタンを押せない。SP-05 ／ D-08

作成の失敗・10秒で打ち切り「失敗しました。もう一度お試しください」と再試行。失敗ならリンクは作られない（打ち切り後に裏で作られることは許す）。SP-05 ／ #30 C

選び直す選び直したら、同じ選び方でも毎回新しいリンク。作成済みのリンクの中身は変えない。SP-07 ／ D-05

受入基準との対応
  • AC-01：価格帯（3,000〜4,999円）・送別を選び、1つ以上選んで共有リンクを作る → 1回の操作の流れの中で作られる（段1〜4）
  • AC-02：そのリンクをログインなしでスマホ幅で開く → 選んだ候補がすべて、理由の文つきで表示される（段6）

② システム視点：画面 ⇄ API ⇄ DB

3つの API を、上から順に処理の流れで描く。画面APIDB は処理する場所。10秒を超える問い合わせは画面・API とも打ち切り、500 に。

A. 候補を出す　GET /api/candidates?price_band=…&scene=…

画面価格帯・シーンを選ぶ → 検索 価格帯は3ボタン（任意）。10秒で打ち切り、以降の応答は捨てる。 D-08 ／ SP-01 ／ #49-1〜3, #30 J
↓
API入力検証 price_band は under3000／3000to4999／5000plus（任意）。scene は お礼/誕生日/送別。 D-01 ／ SP-01
422invalid_price_band / invalid_scene（画面からは起きない。API に直接届いたとき）
↓
DB候補の抽出（読み取りのみ） 商品 × シーンタグ。シーン一致・在庫≧1・価格が選んだ価格帯（税込。価格帯なしは価格で絞らない）。 D-01 ／ SP-01
0件200 で items:[] → 画面が「条件に合う商品がありません…」
10カテゴリー＝products.categoryR-01 の絞り込みと R-02 の絞り込みで使う。
↓
DB送別回数の都度集計（保存しない） 候補の商品IDだけ。注文のうち推定シーン＝送別かつ会社宛て。0件の商品は回数0。 D-04 ／ DATA-01
注文テーブルの列の実名・会社宛ての見分け方（未決1）DB 接続後に Exhibit 4 の実物で確認。
↓
APIベイズ平均で順位付け → 上位10件 点数＝(v÷(v＋20))×R＋(20÷(v＋20))×C。C は評価のある候補の平均。評価か件数が無ければ v＝0。同点は送別回数の多い順→商品ID順。 D-02 ／ SP-02 ／ F-01a
↓
API理由の文を作る（テンプレート、AI なし） 値のある材料の文だけをつなぐ。送別回数0でも「まだありません」。→ 200 { items:[…reason], count } D-03 ／ SP-03 ／ F-02 ／ ADR-003
500・10秒超過DB 障害・Db の10秒上限 → 画面は「失敗しました。もう一度お試しください」＋再試行D-12

B. リンクを作る　POST /api/share-links　{ product_ids:[…] }

API検証product_ids 1〜10件・商品が存在すること。D-05 ／ SP-05
422empty_selection / too_many_items / invalid_product_ids
↓
API作成時点の商品名・価格・理由を作り、22文字の識別子を生成 サーバーが作り直す（画面の値を信用しない）。英大小文字・数字・「-」「_」。毎回新しいリンク。 D-05 ／ SP-05, SP-07 ／ N-02 ／ #30 I
↓
DBshare_links に1行 INSERT share_id（CHAR 22）／ items（JSON：商品ID・名前・価格・理由）／ created_at／is_test。既存テーブルは変更しない。→ 201 { share_id, path, created_at, expires_at } D-07 ／ DATA-02
MySQL 8.4.9 の JSON 型を使うitems は JSON 型。
500・10秒超過失敗なら行は作られない。打ち切り後に裏で作られることは許す。
