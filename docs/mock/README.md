# モック・図の置き場（docs/mock/）

完成イメージ（モック）と図を置く場所です。**モックは2段階**で作ります。仕様がまだ無い間は画面の中身を作りません（仕様に書かれていないことは補わない）。

## 第1段階：要件段階の紙芝居（3〜5枚）

- 目的：要件（F/N）が固まった時点で、「こういう流れで使う」をチーム全員で確認する。
- 形：静止画・簡単な HTML のどちらでもよい。**3〜5枚**で主要な流れを順にめくる。
- 各枚に対応する要件 ID（F/N）を書く。
- 置き場：`docs/mock/kamishibai/`（作成時に追加）

## 第2段階：仕様段階のクリックで動くモック

- 目的：仕様（SP）が固まった時点で、画面遷移と操作を実際にクリックして確かめる。
- 形：素の HTML/CSS/JS（外部ライブラリなし）。
- **各画面に SP 番号を表示する**（どの仕様に対応する画面か分かるように）。
- 置き場：`docs/mock/clickable/`（作成時に追加）

## 案A/案Bの見比べ

決めることがある論点は、`docs/mock/` に案A・案Bを並べ、ハブの「🎨 モック・図」から開く。決定（誰が・なぜ・本人回答）は 5文書の決定事項と `01_ナレッジ/log.md` に残す。

## 見る入口

開発ハブ（`docs/hub.html`）の「🎨 モック・図」から開く。`docs/` はそのまま公開されるので、全員が同じリンクで開け、スマホでも試せる。Artifact は個人の下書きに使ってよいが、正はこのリポジトリ。

## 図の置き場

- 置き場：`docs/mock/diagrams/`（作成時に追加）
- 置くもの：主要フロー図・画面遷移図・ER図。
- 形：Mermaid を書いた `.md`。GitHub の画面で図として見える。

## 守ること

- 実データ・秘匿値は載せない。架空データだけを使う。ここは公開サイトに出る。
