★なぜセットアップするのか

この開発の仕組みは、Munder Difflin で回すように作ってある

講義で説明する仕組みの各段に、Munder Difflin の担当を割り当てた。りじちょーとスタッフ5人は役割ごとに定義してあり、自分待ちは ASK ME に、止める守りはブレーカーと予算に受け持たせている。

講義の仕組みMunder Difflin で担うもの
5文書の壁打ち(講義3章)りじちょー。「○○はどうしますか」と一問ずつ聞き、決めるのは人
Issue → 実装 → PR(講義4章)りじちょーが振り、Takahiro(設計)・Mi-rin(画面)・Terao(API・DB)が作る
書く役と確かめる役を分ける(講義1章)Kurosu が、テスト設計どおりに検証して証拠を残す
人が決めること(講義2章)人にしか進められないものは ASK ME にまとまる
進み具合を見る(講義5章)Tasks と Inbox。その先は GitHub と開発ハブ(下の④)
失敗の吸い上げ(講義7章)yamapi が決定と学びをナレッジに返す。ブレーカーと予算が繰り返しと使いすぎを止める

だから、入れるとこうなる。

①同時に進む

役割の違うスタッフが同時に動く。待たずに別の作業をしてよい。

②判断に集中

話す相手はりじちょーだけ。自分の判断が要るものは ASK ME にまとまり、一行で答えると作業が再開する。

③ミスを防ぐ

書く役と確かめる役が別。同じ動作の繰り返しや使いすぎは、ブレーカーが段階的に止める(促す→読み取りのみ→停止)。使う量の上限(予算)も決められる。

④ひと目で分かる

Tasks に仕事がカード(todo / doing / blocked / done)として流れる。エージェントをクリックすると端末の様子が見え、返事は Inbox に会話ごとに残り、自分待ちは「Asks me」で絞れる。使用量と予算はエージェントのパネルで見られる。その先は GitHub の Issue・PR と開発ハブで、チーム全員が同じ進み具合を見られる。

※ Inbox・Tasks の呼び名は Pro の画面のもの。無料版での見え方は未確認。

使う前 → 使った後

前（使う前）
  • 頼み方　AI に1つずつ直接頼み、返事を待つ
  • 待ち時間　終わるまで画面の前にいる
  • 自分の役目　作業と判断を両方する
  • 進み具合　聞いて回る、または自分で追う
後（使った後）
  • 頼み方　りじちょーに頼み、スタッフに振られて同時に進む
  • 待ち時間　別の作業をして、報告・PR・ASK ME が来たら見る
  • 自分の役目　確認と判断が中心
  • 進み具合　Tasks と開発ハブで、全員が同じものを見る

つなぎこのガイドで、その入口である「りじちょーに指示を出し、スタッフが PR まで進める」状態を、自分の PC で作る。まず、終わったときの姿と完了チェックから見る。

4使い方の考え方と基本操作6分

ねらい「りじちょーに指示 → 確認と判断」を、1つ頼んで実際に回してみて掴む。

考え方

  • 人が話す相手はりじちょーだけ。りじちょーがスタッフに振り、まとめて返す。
  • スタッフが動いている間、あなたは別の作業をしてよい。戻ったら、報告・PR・ASK ME を見て確認と判断を繰り返す。
  • スタッフへの直接指示は例外。
  • 効果: 作業が並行で進む／自分は判断に集中できる。

やること

  1. りじちょーに、次の1行を送る(コピーして使える)。

スタッフ一覧を教えて。名前と役割を1行ずつ。

  1. 左サイドバーの Inbox(会話ごと)を開く。りじちょーの返事が出る。

  2. Tasks

    (todo / doing / blocked / done)を開く。いまの依頼がカードで流れていくのを見る。「Asks me」で、自分待ちのカードだけに絞れる。Inbox・Tasks の呼び名は Pro の画面のもの。無料版の見え方は未確認。

  3. ASK ME のカードが出たら、一行で答える。答えるとタスクが再開する(出なければ、この手順は飛ばしてよい)。

  4. 返事が長い・止まったときは、エージェントをクリックすると端末の様子が見える。変更を見るときはエージェントのパネルの IDE。

  5. 知っておく: ブレーカー(同じ動作の繰り返しや使いすぎを見張り、steer → constrain → stop の順に止める)と、予算(エージェントの側パネルの Budget)。「Circuit breaker: steer」が来たら、繰り返しをやめ、試したことをまとめて指示に従う。使用量の表示場所は未確認。

6オプション：定期実行（週1要約・AI レビュー）約10分（任意。本編の31分に含めない）

ねらい設定しておくと、開発が自動で楽になる。

6-1. 何が良くなるか

機能良くなること自分の PC での設定
週1要約失敗の記録を毎週月曜 09:00 に「型」にまとめる。2回以上出た型は CLAUDE.md の「よくあるミス」に載り、次から防がれる要る(Mac: launchd／Windows: タスクスケジューラ)
AI レビューPR の完了条件を AI が1行ずつ判定する。レビュー待ちが減る要らない(claude.ai の画面で作る。Mac も Windows も同じ)
  • 失敗の記録(hook)は設定済み。ここで入れるのは「毎週まとめる」と「PR を自動で判定する」の2つ。
  • 週1要約が作る PR は CLAUDE.md を変えることがあり、needs-human が付く。人が見る。
  • claude -p はトークンを使う。記録が空の週は起動しない。

6-2. 週1要約 — 前提

  • Git、Python 3、GitHub CLI(gh)、Claude Code が入っている。gh auth status が Logged in to github.com、claude は一度ふつうに起動してログイン済み(claude --version が通るだけでは足りない)。
  • 管理者権限は要らない(Windows は PowerShell を通常起動。管理者で実行しない)。
  • <REPO> = クローンの絶対パス(Mac: cd <REPO> && pwd)。
  • Mac のクローン先:「書類」「デスクトップ」「iCloud」配下は避ける(launchd が読めるか未確認)。
  • Windows:半角英数字のパス推奨(例 C:\work\model_team18_tech0。日本語・空白で動くかは未確認)。Microsoft Store の python エイリアスは「アプリの実行エイリアス」でオフにする。ログオン中だけ動く。

期待: バージョン／Logged in to github.com／.githooks。出ない行は先に直す。

  1. 試走(ファイルは変えない。git は fetch だけ行う)。画面には何も出ず、ログに出る。

scripts/scheduled/run-digest.sh --dry-run
cat ~/Library/Logs/munder-scheduled/$(ls -t ~/Library/Logs/munder-scheduled | head -1)

ログ先頭に digest start repo=… が出ればよい。

  1. claude まで通す。

    手順2は、01_ナレッジ/_inbox/mistakes.jsonl が空だと、claude を起動する前に「今週は記録なし」で終わる(ログインや許可ツールは試されない)。Claude Code をこのリポジトリで起動し「git nope を実行して」と頼む(hook が記録を1行作る)。そのあと手順2をもう一度。ログに「今週は記録なし」が出ず、claude の報告が出れば合格。

  2. 登録。

cd <REPO>

grep REPO は何も出ないのが正しい(<REPO> の文字が残っていないか)。plutil は OK。

  1. 今すぐ1回走らせる(本番。PR ができる可能性あり)。手順3で作った試し記録も要約に入る。

launchctl kickstart gui/$(id -u)/com.munder.digest

PowerShell に貼る。<REPO> を置き換える。すべて Windows 実機では未確認

  1. 事前確認と1回だけの設定。

cd <REPO>
git --version; python --version; gh auth status; claude --version

git config core.hooksPath

最後の出力が .githooks。

powershell -NoProfile -ExecutionPolicy Bypass -File scripts\scheduled\run-digest.ps1 -DryRun

ログ先頭に digest start repo=…。

  1. claude まで通す。

    Mac の手順3と同じ(「git nope を実行して」で 01_ナレッジ\_inbox\mistakes.jsonl に記録を作り、手順2をもう一度)。

powershell -NoProfile -ExecutionPolicy Bypass -File scripts\scheduled\register-digest-task.ps1 -Action RunNow

6-4. 週1要約 — 成功の確かめ方

Mac

  • 登録できた(Mac): plutil -lint が OK。launchctl list | grep com.munder に com.munder.digest。

Windows

  • 登録できた(Windows): 登録しました: MunderDigest（毎週月曜 09:00…）。-Action Status で NextRunTime が次の月曜 09:00、状態: Ready。
  • 走った: ログ(Mac: ~/Library/Logs/munder-scheduled/digest-*.log／Windows: %LOCALAPPDATA%\munder-scheduled\digest-*.log)が増え、末尾に digest end。Windows は LastTaskResult が 0。
  • 記録がある週: ブランチ chore/knowledge-digest-<日時> から PR が1つできる。CLAUDE.md を変えたら needs-human。本番の PR 作成は【実機確認なし】(Mac は launchd 経由の自動起動も未確認)。
  • 記録が空の週: ログに「今週は記録なし」。PR は作られない(正常)。
  • 自分の作業中のクローンは触られない(別の作業ツリーで作業して、終わると消える)。

6-5. 週1要約 — 止め方・やり直し

Mac

  • Mac 一時停止: launchctl bootout gui/$(id -u)/com.munder.digest(plist は残る)。
  • Mac 外す: 上の bootout のあと rm ~/Library/LaunchAgents/com.munder.digest.plist。走行中を止めるなら pkill -f run-digest.sh。
  • Mac やり直し(plist を直した／パスが変わった): bootout → 6-3 の手順4の sed で plist を作り直す → launchctl bootstrap …。登録したままの bootstrap は失敗する(Bootstrap failed: 5: Input/output error など。一般知識)。

Windows

  • Windows 外す: … register-digest-task.ps1 -Action Unregister。
  • Windows やり直し: -Action Register を再実行(上書き)。
  • ロックが残った: 走っていないことを確認し、Mac: rmdir ~/Library/Logs/munder-scheduled/digest.lock／Windows: Remove-Item -Recurse $env:LOCALAPPDATA\munder-scheduled\digest.lock。
  • 試しに作った記録を消すなら _inbox/mistakes.jsonl の該当行を消す。

6-6. AI レビュー（クラウドのルーチン。Mac も Windows も同じ）

前提

  • オーナーが Claude GitHub アプリを Organization に入れ、対象リポジトリを選んでいる(初めての人の作業ではない)。
  • 自分の claude.ai アカウントがルーチンを使えるプラン(Pro/Max/Team/Enterprise)。Team/Enterprise は owner が Scheduled tasks を有効にしている。
  • 作業中の PR は Draft で出す(Draft では起動しない)。作者本人の PR は飛ばされるので、レビューが動くのは他の人の PR。

手順（画面操作。文言は実画面に合わせる）

  1. https://claude.ai/code/routines を開き、New task(New routine)。

  2. Name: PR レビュー。

  3. Instructions: 指示文の本体は貼らない。起動文だけを貼る。本体は毎回 main の scripts/scheduled/review-routine-prompt.md(「---」より下)から読まれる。

このリポジトリで `git fetch origin main` を実行し、`git show origin/main:scripts/scheduled/review-routine-prompt.md`（「---」より下）と `git show origin/main:00_ルール/PRレビュー規定.md` を読んで、その指示に従って PR レビューを実行する。作業ツリーのファイルは使わない。

  1. Trigger を2つ。(a) GitHub event → Pull request → opened、フィルタ Author is one of(対象3人の GitHub 名)と Is draft equals false。synchronize は選ばない。(b) Schedule → Custom → cron 0 23 * * *(UTC。毎日 JST 8:00)。

  2. Advanced settings: Repository model_team18_tech0。Cloud environment は api.github.com に届く設定(既定で足りるかは未確認)。不要なコネクタは外す。

  3. Create。詳細ページで Run now を1回。

成功の確かめ方（Run now の結果）

  • JST 1〜7 時なら「休止時間のため終了」とだけ報告して何もしない。
  • 対象 PR が0件なら「対象 PR なし」で終わる。
  • 他の人の PR があれば ai-review:doing が付き、コメントが投稿され、ai-approved か needs-human に付け替わる。ラベル・承認の付与が実際にできるかは【実機確認なし】。付けられない(403)ときは、コメント1行目の見出し(【AIレビュー中】/【AI承認可】/【要人レビュー】/【要人レビュー：承認投稿不可】)で代用される。
  • 実測(god のルーチン実行履歴): Draft でない試験 PR は作成2秒後に起動、Draft では起動しなかった。

止め方

  • 一時停止: ルーチン詳細ページ上部の on/off スイッチ(設定は残る)。トリガーだけ外す: Edit。消す: Delete。
  • GitHub 接続が切れると最大72時間スキップされ、自動で off になる。
  • 指示文を直したいときは、画面ではなく scripts/scheduled/review-routine-prompt.md を PR で直す(needs-human になる)。
