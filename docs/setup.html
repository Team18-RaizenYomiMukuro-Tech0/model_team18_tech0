3使い方の考え方と基本操作6分

ねらい「りじちょーに指示 → 確認と判断」の回し方を掴む。

考え方

  • 人が話す相手はりじちょーだけ。りじちょーがスタッフに振り、成果をまとめて返す。
  • スタッフが動いている間、あなたは別の作業をしてよい。戻ってきたら、報告・PR・ASK ME を見て、確認と判断を繰り返す。
  • スタッフへの直接の指示は例外(細かい修正をその人に伝えたい時など)。
  • 効果：作業が並行で進む／自分は判断に集中できる。

やること

  1. りじちょーに、成果・対象フォルダ・完了の条件を書いて頼む。クリックすると端末の様子が見える。

  2. 返事は Inbox(会話ごと)、作業の流れは Tasks(todo / doing / blocked / done)で見る。「Asks me」で自分待ちのカードだけ出せる。Inbox・Tasks の呼び名は Pro の画面のもの。無料版の見え方は未確認。

  3. ASK ME のカードが出たら、一行で答える。答えるとタスクが再開する。

  4. 変更を見るときはエージェントのパネルの IDE。

  5. ブレーカー：同じ動作の繰り返しや使いすぎを見張り、steer(促す)→ constrain(読み取りのみ)→ stop(停止)の順に止める。「Circuit breaker: steer」が来たら、繰り返しをやめ、試したことをまとめて指示に従う。

  6. 予算：エージェントの側パネルの Budget(期間と上限)。全体の予算は Pro は「Budget & breaker」タブ、Classic は Settings → Autonomy & Budgets。使用量の表示場所は未確認。

注意
  • 新規インストールの既定は Autonomous(確認なしで動く)。頼み方は慎重に。
  • スタッフに話した内容は Issue か PR に書かないと他の人に届かない。hive/ は PC ごとに別。

5練習：ダミー Issue から PR まで8分

ねらい「指示 → 確認と判断」を一周し、同時にスタッフが動くことを確かめる。PR が出れば用意完了。

やること

  1. りじちょーに、下の指示を貼る(コピーして使える)。

ダミーの練習をしたい。次の順で進めて。
1. .github/ISSUE_TEMPLATE/task.md の形で、練習用の Issue を1つ作って。内容は「00_ルール/ 以外の、練習用ファイル practice/hello.md を新規に作り、1行目に『こんにちは』と書く」。完了条件は、ファイルが存在し1行目が『こんにちは』であること。
2. その Issue をスタッフ(Terao など1人)に割り振って、ブランチで作業させて。
3. PR は Draft で出し、本文に Closes #<Issue 番号> を入れて。
4. 出来たら、PR の番号と完了条件ごとの証拠を報告して。

  1. りじちょーが、1章でログインした gh を使って Issue を作る。出来た Issue の番号が報告に載る。

  2. スタッフが作業している間、別の作業をしてよい。ASK ME が出たら一行で答える。

  3. 報告が来たら、GitHub で PR を開き、完了条件の証拠が揃っているか、機械チェック(テンプレート記入)が pass かを見る。足りなければ、りじちょーに伝える。

  4. PR が出たら、用意完了。その PR はマージせず閉じる

    (GitHub の PR 画面で「Close pull request」)。作業ブランチは削除してよい。練習用の Issue も閉じる（Issue 画面で『Close issue』）。

できたかの確認

ハマりどころ
  • Issue のない PR は AI レビューが承認しない。練習でも Issue から始める。
  • 練習 PR をマージすると main に残る。閉じること。
