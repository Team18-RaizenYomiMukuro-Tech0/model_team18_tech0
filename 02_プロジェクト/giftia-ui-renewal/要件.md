# 要件 — Giftia UI/UX リニューアル

優先: R-01 を先に仕上げ、R-02 は R-01 に必要な部分（条件での絞り込み・候補選び・詳細）だけ先に作る（ADR-002）。

## 機能要件

| 要件ID | 要求ID | 満たすこと | 測定できる基準 |
| --- | --- | --- | --- |
| F-01 | R-01 | 利用者の入力（予算の総額（任意。#39）・シーン）を受け、商品 DB から複数の候補を取り出し、チームが設計したロジックで順位付けして返す（ケース Exhibit 5 の必須の流れ） | 送別・予算 4,500円の入力で、送別タグを持ち予算内の商品だけが、順位付きで返る。順位付けのルールは F-01a と仕様 SP-02 |
| F-01a | R-01 | 順位付けのロジック: 評価の高い順。ただし件数が少ない商品は割り引く（質問22「B」） | 評価4.9・3件より評価4.6・120件が上に来る。割り引きの式と係数は仕様で定義 |
| F-02 | R-01 | 各候補に、仲間の同意の材料になる理由を付ける。理由は既存の列の組み合わせだけで作る（ADR-003、質問20「C」、#23・#29） | 事実をテンプレートでつなげた自然な文で表示する（AI は使わない。30字の制限なし、分かりやすさ重視）。材料は「職場の送別で贈られた回数（注文の推定シーン＝送別かつ会社宛ての件数）」「評価と件数」「配送日数・ラッピング可」。値が無い材料は使わない。値を作らない |
| F-03 | R-01 | 候補を選んで、まとめておける | 1つ以上、上限なしで選べる（#23） |
| F-04 | R-01 | 選んだ候補をまとめた共有リンクを作る | サイトを閉じずに、1回の操作の流れの中でリンクが作られる（AC-01） |
| F-05 | R-01 | 共有リンクをログインなしで開ける | ログインなしでスマホ幅の画面から開くと、選んだ候補と理由が表示される（AC-02） |

R-02 の機能要件は、要求.md の旧 ID 対応表（HDR・SRC・FAV・RAT 等）を元に、R-01 に必要な部分から追記する。

## 非機能要件

| 要件ID | 要求ID | 性能・使いやすさ・環境・安全 | 測定できる基準 |
| --- | --- | --- | --- |
| N-01 | R-01 | 共有リンクはスマホで読める | スマホ幅 375px（OPEN-01 で決定）で、横スクロール・文字欠けが無い |
| N-02 | R-01 | 共有リンクは他人に推測されにくい | リンクの識別子は連番ではなく、推測しにくい値にする（具体は仕様） |
| N-03 | R-01 | 待たされずに進める（速さ） | 手元の PC から班の DB につないで各10回測り、遅い方から2番目の値で、候補表示2秒以内・共有リンク作成1秒以内・共有ページ表示1秒以内。性能テストで測り数値を証拠に残す。超えたら注文テーブルへの索引追加を設計し、既存テーブルの変更なので足す前にレージに確認する（キックオフ記録 #34 7-1・7-2） |
| N-04 | R-01 | DB を守る | 問い合わせは必ずパラメータ化クエリ（入力値を SQL 文に直接つなげない）。DB との通信は SSL（#28 の証明書）。接続アカウントは既存テーブルの読み取りだけ、書き込みは共有リンク用テーブルだけ（#34 7-3） |
| N-05 | R-01 | 表示した文字でスクリプトが動かない | 画面に出す文字は必ずエスケープする。React の通常の表示だけを使い、HTML をそのまま差し込む書き方を禁止する（#34 7-4） |
| N-06 | R-01 | 使いすぎを防ぐ | 共有リンク1本に入れられる商品は10件まで。11件以上で作ろうとしたら入力エラー。画面での選択は上限なしのまま。作成回数の制限は外部公開の承認後に決める（#34 7-5） |
| N-07 | R-01 | 共有ページを広く公開しない | 共有ページは検索エンジンに載せない（noindex）。API は自サイトの画面からだけ呼べるよう CORS を絞る（外部公開の承認後に設定）（#34 7-6） |
| N-08 | R-01 | 費用を抑える | 運営が用意した範囲（班の DB、承認された Azure の枠）を使う。チームが払う費用は開発段階で合計500円以内。お金がかかるサービス・設定は使う前にレージと運営の承認を取る。生成AI の API は使わない（ADR-003）（#35 8-1） |
| N-09 | R-01 | 失敗したら元に戻せる | アプリは前のコミットに戻して入れ直す（公開中なら公開を止める）。DB は共有リンク用テーブルを消せば元どおり（既存テーブルは変えない）。テーブルの作成・行の削除・テーブルの削除は、アプリとは別の管理用アカウントでレージが手で行う（手順は Terao）。テストで作った行は、テスト用の印の付いた行だけを消す（#35 8-2） |
| N-10 | R-01 | 試験のしかた | 手元の PC から班の DB `giftia_t501` に接続して試す（外部公開の承認まで手元だけ）。架空データだけを使い、テストで作る共有リンクにはテスト用の印を付ける。単体・結合・システム・受入がすべて通れば合格、結果は `evidence/` に残す。N-03 の速さは API にリクエストを送ってから応答が返るまでを測り、作成と表示は商品10件、1回目も数える（#35 8-3） |
| N-11 | R-01 | 動く環境 | 共有ページは iPhone の Safari と Android の Chrome の最新版、検索ページは PC の Chrome の最新版で動く。外部公開の承認までは PC の Chrome で幅を縮めて確かめ、承認後に iPhone・Android の実機で1回ずつ確かめる（#35 8-4） |
| N-12 | R-01 | 迷わず操作できる | 予算とシーンを入れてから共有リンクをコピーするまで、候補を3つ選ぶ場合で9回以内の操作（予算の入力も1回に数える。#38）。押す場所は縦横44px 以上。文字と背景の色の差は WCAG AA。主要な流れはキーボードだけでも進める（#35 8-5） |
| N-13 | R-01, R-02 | 法令・決まりを守る | 個人情報は集めない・保存しない（共有リンクに保存するのは商品の情報と作成日時だけ）。アプリのログに IP アドレスとブラウザの情報は残さない（残すのは時刻・API・結果だけ。#39-6）。価格は税込で、価格の後ろに「（税込）」と表示し（#39-7）、画像は「イメージ」と明記する（OPEN-03・06）。商品データとケース資料は授業の中だけで使い、外部公開の承認まで外へ出さない（#35 8-6） |

| N-15 | R-01 | リンクが広まっても困らない | 新しい仕組みは作らず、N-02（推測できない識別子）・N-07（noindex）・720時間の期限・N-13（個人情報なし）で守る。共有ページに「このページはリンクを知っている人なら誰でも見られます」と小さく書く。LINE 等で送ったときのプレビューは商品名を出さず「Giftia の贈りもの候補」だけ（#35 8-8） |

開発フロー §5 との照合（2026-11-07）: 必須5つ — 速さ N-03／安全 N-02・N-04〜N-07／費用 N-08／戻し方 N-09／試験のしかた N-10。確認5つ — 環境 N-11／使いやすさ N-01・N-12／法令 N-13／保守 N-14／共有への備え N-15。すべて関係ありと判断（レージ回答 #35）。

## 通常ルート

架空データを使う。秘密情報をコミットしない。mainへ直接pushしない。入力検証とエラー処理を保つ。

技術条件（ケース Exhibit 5）: フロントエンド Next.js、バックエンド FastAPI、DB はケース提供の MySQL（班の DB `giftia_t501`）。
