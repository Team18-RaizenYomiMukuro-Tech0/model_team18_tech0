- **版**: 評価を始める前に、評価する `main` のコミット ID を 1 つ決めて、#237 の評価計画のコメントに書く。各 `evidence/<ID>.md` の「実行」行にも同じコミット ID を書く（`git rev-parse --short HEAD` の出力）。評価中は #219 の backend 変更を入れない（#242）。
- **決める人・決め方**: 未決（PM・りゅうちゃんが決める）。テスト設計.md の「対象版と承認」はコミット ID・承認記録とも未記入。
- **場所**（テスト設計.md「前提」・各行の「場所」列）:
  | 種類 | 場所 |
  | --- | --- |
  | U | 手元 PC（偽の DB。DB は使わない固定データ FD-1〜FD-10） |
  | I・S・E | 手元 PC。「【場所】班の DB」と書いた行（I-06・I-15・I-16・I-19・I-29・E-08・NF-18・NF-19）だけ班の DB `giftia_t501` |
  | NF-01〜04・36〜39 | 手元 PC から班の DB につなぐ（テスト設計.md「非機能テスト」の冒頭） |
  | NF-23 | 公開後の iPhone Safari（実施はりゅうちゃん。Android は PC の Chrome 幅縮め 375px で代える。NF-22・設計.md） |
- **公開サイトで回すか、手元で回すか**: 評価全体としては未決（PM・りゅうちゃんが決める）。公開後でないとできない NF（NF-14・15・23・42 など）をどの版・どの場所で回すかも、同じく未決。

## ⑤ 証拠の名前と置き場

`evidence/README.md` と今の `evidence/` の実態に合わせる。

| 何を | 名前・置き場 |
| --- | --- |
| テストごとの判定 | `evidence/<テストID>.md`（例: `I-06.md`）。1 行目に ○ か ×（`# I-06 — ○`）、期待結果、実行（だれ・日時・場所・版・コマンド）、根拠、証拠パス |
| 画面の証拠 | 同名の画像 `evidence/<テストID>.png`。複数なら `<テストID>_<番号>_<内容>.png`（例: `S-23_1_under3000.png`）、幅別は `<テストID>_375.png`・`_1280.png` |
| 再判定 | `<テストID>_再判定.md`（例: `S-22_再判定.md`） |
| DB の実行記録 | `evidence/db/<日付>_<番号>.md`。接続情報は書かない |
| ○× の一覧 | 段ごとの `T2_一覧.md`・`R11_一覧.md` と同じ形（#237 完了条件 #2） |
| 自己評価・受入 | `evidence/self-review.md`、`evidence/A-01.md`〜`A-12.md` |

パスを示せないものは証拠にしない。△は使わない（`evidence/README.md`）。
