## 外部公開

Azure の無料のプランに、画面（Next.js）と API（FastAPI）を置く。運営が用意した枠があれば、そちらを優先する。
URL を知っている人だけが開ける形にする。URL が漏れても困らないように、データは授業のサンプル（架空）だけにする。
検索エンジンには載せない。robots.txt ですべて拒否し、X-Robots-Tag: noindex を付ける。
API は、画面のドメインからの通信だけを受け付ける（CORS で制限する）。
期間は 11/12 から 12/12（発表後のフィードバック期間の終わり）まで。12/12 にApp Service を止め、作ったリソースを削除する。

## ログイン

本番の公開版には作らない。ヘッダーは「準備中」のままにする（SP-08）。
実装が終わった後、勉強のために手元の PC だけで試作する。試作は公開せず、別のブランチに置く。公開は main ブランチからだけ行う。
試作用のユーザーは、手元の DB（SQLite など）に置く。班の DB giftia_t501 と、その中の users には触れない。
パスワードは bcrypt でハッシュにして保存する。
方式は、セッション Cookie 方式と JWT 方式を手元で比べて、違いを確かめる。

## DB のアカウント

アプリ用のアカウント giftia_app を足す。既存の表は読むだけ（SELECT）、share_links は読むのと足すだけ（SELECT・INSERT）にする。更新（UPDATE）と削除（DELETE）の権限は付けない。
share_links の表を作る（CREATE TABLE）のと、期間が終わった後に表を消す（DROP）のは、配られたアカウントで手で行う。テスト用の行を消すのも、同じアカウントで手で行う。
giftia_app のパスワードは Azure のアプリの設定（環境変数）に置き、リポジトリには入れない。

## 基盤側のログ

Azure のアクセスログは、記録を追加でオンにしない。IP が残っても外には出さず、保存期間は初期のままにする。見るのは障害の対応で必要なときだけにする。
アプリ自身のログには IP を残さない（N-13）。FastAPI（uvicorn）は初期設定のままだと接続元の IP をログに出すので、アクセスログをオフにする（--no-access-log）。

## 実機での確認

公開後、メンバーの iPhone（Safari）と Android（Chrome）で、共有ページを 1 回ずつ開く。データは架空のものだけを使う。
確かめるために作ったリンクは、ID を控えておく。確認した当日中に、配られたアカウントで手で消す。

## URL のドメイン

Azure が自動で付けるドメイン（〜.azurewebsites.net）を使う。独自のドメインは買わない（0 円）。

## 費用

無料のプランだけを使うので、見込みは 0 円。
0 円を守るために、次のようにする。
App Service プランを作るときは、F1（Free）を自分で選ぶ（初期の選択は有料のことがあるため）。
Application Insights はオフにする。
コンテナではなく、コードのままデプロイする（Container Registry は有料のため）。

週に 1 回、すべてのリソースが無料のプランのままか、Azure の画面で確かめる。
費用の画面を見られる場合は、念のため予算アラート（例：500 円）を設定。
