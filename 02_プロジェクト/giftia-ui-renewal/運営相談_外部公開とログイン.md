# 運営への相談（下書き）— 外部公開とログイン

チーム18 / 案件: Giftia UI/UX リニューアル / 起票: りじちょー（下書き）、送付: レージ
関連: `ADR.md` ADR-004（外部公開）、`要求.md` OPEN-05（ログイン）

CLAUDE.md の決まり（認証・外部公開は、実装・設定・公開の前に運営へ相談し、承認された範囲だけ進める）に従い、次の2点の承認をお願いします。承認までは、手元の PC での開発とテストだけを進めます。

## 相談1: アプリの外部公開

| 項目 | 内容 |
| --- | --- |
| 目的 | 共同購入者が、候補をまとめた共有リンクを仲間（Giftia を使わない人）にスマホで見せられることを、本番に近い形で確かめる |
| 公開するもの | Next.js（フロントエンド）と FastAPI（バックエンド）のアプリ。URL を知っている人が開ける |
| 置き場所（希望） | Azure（使ってよいサービスの種類を教えてください） |
| 使うデータ | 班に配布された架空のダミーデータ（Azure 上の MySQL `giftia_t501`）。実データ・個人情報は使わない |
| 書き込み | 共有リンク用の新しいテーブル1つ（選んだ商品の作成時点の商品ID・商品名・価格・理由の文と、作成日時。個人情報なし）。既存テーブルは変更しない |
| リスク | 公開 URL から DB に過大な負荷がかかる／共有リンクの識別子を推測される／接続情報の漏れ |
| 対策 | 識別子は推測できない22文字以上のランダム文字列。リンクは作成から720時間（30日）で期限切れ。入力は検証し、予算は1,000〜999,999円の整数だけ受け付ける。DB の接続情報は環境変数に置きコミットしない（SSL 接続）。読み取り以外の書き込みは共有リンクのテーブルだけ |
| 公開の期間 | 希望: 評価期間の終わりまで（運営の指定に従います） |
| 戻し方 | Azure 上のアプリを停止・削除する。共有リンクのテーブルを削除する（既存データには影響しない） |

## 相談2: ログイン（認証）

| 項目 | 内容 |
| --- | --- |
| 目的 | PDF の要求（ヘッダーのログイン入口）に沿って、ログインの中身を作る |
| 現状の方針 | 承認までは、入口に「準備中」と表示するだけ。お気に入り・カートはブラウザ内保存でログイン不要 |
| 相談したいこと | 認証を実装してよいか。よい場合、使ってよい方式（例: 自前のパスワード認証、外部の認証サービス）と、会員データ（ダミーの users）の使い方 |
| リスク | パスワードの保存・漏えい、認可の抜け（他人のデータが見える） |
| 戻し方 | ログイン機能を無効にし、入口を「準備中」に戻す |

## 相談3: DB のアカウントと権限

| 項目 | 内容 |
| --- | --- |
| 目的 | 要件 N-04・N-09 のとおり、アプリが使うアカウントの権限を最小にし、テーブルの作成・削除は別の管理用アカウントで人が手で行う |
| 相談したいこと | 班の DB `giftia_t501` で (1) アカウントを追加してよいか（アプリ用: 既存テーブルは SELECT のみ、共有リンク用テーブルは SELECT・INSERT のみ） (2) 配布されたアカウントに CREATE・DROP・DELETE・GRANT の権限があるか (3) 追加できない場合、配布されたアカウント1つで進めてよいか |
| リスク | アプリ用アカウントの権限が広いと、不具合や攻撃で既存データを書き換えられる |
| 戻し方 | 追加したアカウントを削除する。共有リンク用テーブルを削除する |

## お願い

- 相談1・2 それぞれについて、可否と、承認する範囲（サービス・期間・条件）を教えてください。
- 返事は `ADR.md` の ADR-004（と新しい ADR）に記録し、承認の範囲だけを実装します。
