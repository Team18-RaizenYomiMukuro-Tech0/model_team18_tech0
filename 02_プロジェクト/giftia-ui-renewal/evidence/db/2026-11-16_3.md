## 手順 3d（`share_likes` の後片付け。手順 3 の前に流した）

`db_admin.py` に 3d は無い（`DB管理手順.md` の注）。同じ接続（`db_admin.open_connection()`、autocommit なし）で、手順書の 3d の SQL（WHERE は手順書のとおり）を流した。件数が想定（3）と違えば ROLLBACK する形。使い捨ての短い script で、コミットしていない。`2026-11-15_3_2.md` と同じ形。

| 確認 | 件数 |
| --- | --- |
| 流す前の `share_likes` 全体 | 7 |
| `to_delete`（手順書の 3 条件のどれか。依頼の想定は 3） | 3 |
| `DELETE` の `ROW_COUNT()` | 3（`to_delete` と一致。COMMIT） |
| 流した後の `share_likes` 全体 | 4（`is_test=0` の共有リンクの分だけ） |
| 流した後に条件へ当てはまる行 | 0 |
| `share_links`（この手順の前後） | `is_test=1` が 10、`is_test=0` が 9 のまま |

## まとめ（前後の件数）

| 時点 | `share_links` 全体 | `is_test=1` | `is_test=0` | `share_likes` |
| --- | --- | --- | --- | --- |
| 流す前 | 19 | 10 | 9 | 7 |
| 流した後 | 9 | 0 | 9 | 4 |

- 流す前の件数は依頼の想定（`is_test=1` が 10、3d の対象が 3）と一致したので流した。`is_test=0` の 9 行と、それに付く `share_likes` 4 行には触れていない。`--force` なし。pytest は流し直していない。

### 手順 3d で流した文（WHERE まで、流した文そのまま）

使い捨ての script が `START TRANSACTION` のあとに流した文。`W` は 3 つの条件（(a) `is_test=1` の共有リンクの分、(b) 作成から 720 時間を過ぎた共有リンクの分、(c) 共有リンクの行がもう無い分）で、手順書の 3d の WHERE と同じ。

```sql
SELECT COUNT(*) AS n FROM share_likes;
SELECT COUNT(*) AS n FROM share_likes WHERE share_id IN (SELECT share_id FROM share_links WHERE is_test = 1) OR share_id IN (SELECT share_id FROM share_links WHERE created_at < UTC_TIMESTAMP() - INTERVAL 720 HOUR) OR share_id NOT IN (SELECT share_id FROM share_links);
START TRANSACTION;
DELETE FROM share_likes WHERE share_id IN (SELECT share_id FROM share_links WHERE is_test = 1) OR share_id IN (SELECT share_id FROM share_links WHERE created_at < UTC_TIMESTAMP() - INTERVAL 720 HOUR) OR share_id NOT IN (SELECT share_id FROM share_links);
-- ROW_COUNT が to_delete（3）と一致したので COMMIT（違えば ROLLBACK する形）
COMMIT;
SELECT COUNT(*) AS n FROM share_likes WHERE share_id IN (SELECT share_id FROM share_links WHERE is_test = 1) OR share_id IN (SELECT share_id FROM share_links WHERE created_at < UTC_TIMESTAMP() - INTERVAL 720 HOUR) OR share_id NOT IN (SELECT share_id FROM share_links);
SELECT is_test, COUNT(*) AS n FROM share_links GROUP BY is_test;
```

- 2 本目の `SELECT COUNT(*)`（`WHERE` つき）が `to_delete`（結果は 3）。`DELETE` の WHERE はこれと同じ。消した行の `share_id` の一覧は、実行前に手順書の 3d の 3 本目の `SELECT`（`LIMIT 50`）では出していない（件数の一致だけで確かめた）。
