## 5. 入れる順番（承認が出た場合）

1. **PM が道具を決める。** 3.3 の 2 点（Playwright・Vitest）と、CI をどうするか（6 節）。
2. **描画テストを 1 本だけ先に動かす。** R-01 を入れ、`next/image`・`next/link`・CSS Modules が jsdom で動くかを確かめる。動かなければ、そこで止めて報告する。
3. **描画テストを 24 本まで増やす。** 区切りの前に、PR を分ける（部品ごとに 5〜8 本）。
4. **通しの確認を 1 本だけ先に動かす。** E2E-1 で、`/api/*` の差し替えと「差し替え先が無い通信を失敗にする」仕組みを確かめる。
5. **通しの確認を 6 本まで増やす。** CI のジョブを足す。
6. **実測を書く。** CI の時間・本数・不安定さ（同じ PR で 3 回回して、結果が揺れないか）を、この文書の 3 節に書き足す。

## 6. PM に決めてもらうこと

1. **道具を入れてよいか。** Playwright と Vitest（＋ Testing Library・jsdom）。`package.json` と `package-lock.json` が変わります。
2. **Playwright のブラウザ取得を認めるか。** CI からブラウザの配布元へ通信します。運営への相談が要るかも合わせて決めてください。
3. **CI にどう入れるか。** 描画テストは `frontend` ジョブに足すか。通しの確認は別ジョブで、PR ごとに動かすか、ラベル付きだけにするか。
4. **本数。** 通し 6 本・描画 24 本でよいか。減らすなら、通しは E2E-4 と E2E-6 を、描画は R-06・R-24 を先に外します。
5. **`npm test` の形。** 別コマンド（`npm run test:ui`・`npm run test:e2e`）にするか、描画だけ `npm test` に足すか。
