# 自己評価（W4）— Giftia UI/UX リニューアル

この表は、W4 の自己評価の**枠だけ**。評価（できた／想定と違った）と根拠・証拠は、これから書く。

- 目的: 自分たちの要求・受入基準（AC-01〜AC-12）に照らして、本番で「できた／想定と違った」を書く（開発フロー §9）。
- 自己評価が先、見直しが後: 先に下の表を埋める。そのあと、時間を置くか別観点（AI スタッフの相互レビュー）で読み直し、「気づいていなかった点」を指摘 ID `X-連番` で足す。
- 結果を見て基準を変えない。変えるなら理由と影響を ADR に書き、本人の再承認を受ける（開発フロー §9）。
- 受入の基準の列は `要求.md` の「受入基準」の表の要約。迷ったら原文（`要求.md`）が正。評価の列・根拠の列は書くまで空にしておく。
