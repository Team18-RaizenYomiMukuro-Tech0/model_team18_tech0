## 1. giftia_app を作れなかった → 案A（#67・#68・#70）

- 事実: 配られたアカウントに CREATE USER・GRANT が無く、アプリ用の `giftia_app` を作れない（Terao が `SHOW GRANTS` で確認。`DB管理手順.md` 穴4）。
- 決定: 案A。公開版も配られたアカウントで班の DB につなぐ。`giftia_app` は作らない。運営のだーあさに確かめ「承知しました」と回答あり（#70）。ADR-004 に理由と影響を記載。
- 影響（記録済みの事実）: 権限を DB で絞れない。配られたアカウントは `giftia_t502`〜`t506` にも書ける。代わりにコードで3つ縛る（接続先は `giftia_t501` に固定・書き込みは `share_links` への INSERT だけ・SQL はすべてプレースホルダ）。Kurosu がテストを足す。
- 学び: 権限を足してもらう相談をする前に、`SHOW GRANTS` で自分の権限を確かめる。

## 2. robots.txt 全拒否と noindex の両立（H-43、#70-3）

- 論点: `robots.txt` で全拒否すると検索エンジンはページを取りに来ないので、`X-Robots-Tag: noindex` を読めない（設計.md の noindex の節に同じ注記あり）。
- 決定: 運営の回答どおり両方行う。`robots.txt` ですべて拒否し、画面の全ページと API の全応答に `X-Robots-Tag: noindex` を付ける。巡回そのものを断るのが主、noindex は念のため。

## 3. SSL は certifi の公開の束で足りた（#71-2、案Q）

- 決定: certifi の公開の証明書の束を使い、ホスト名を確かめる。証明書ファイル・環境変数は使わない。Terao が手元から接続して確認済み（TLSv1.3。`evidence/db/2026-11-08_ssl-certifi.md`、版 fc3e84e）。つながらなくなったら案P（PEM を環境変数に置き起動時に書き出す）に戻す。
- 学び: 秘密でないものに秘密の扱いをしない。
