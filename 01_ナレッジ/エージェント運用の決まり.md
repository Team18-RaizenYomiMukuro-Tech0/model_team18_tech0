# エージェント運用の決まり

AI スタッフ（りじちょー・各スタッフ）の動かし方の決まり。出典は `hive/agents/god/memory.md` の Rules と `hive/board.md`（2026-11-07）。

## 1. 「〜の後に出す」と待たせない

- 依頼に「〜のマージ後に PR を出して」と待ちを書かない。待ちが要るときも、成果物（push・Draft PR）はすぐ出させ、マージの順番は PR 本文に書く。
- 起きたこと: ある依頼の「#102 マージ後に PR」で担当が黙って待ち、PM に「誰も動いてない」と言われた。
- 依頼から10分たって done が無ければ、本人の作業場所・ブランチを見て、止まっていれば自分から動かす。

## 2. ターンの終わりに done か blocked を送る

- 終える前に、依頼が終わっていれば god に done、待ち・詰まり・判断待ちなら blocked（何を待っているか、誰が何をすれば進むか）を1通送る。何も送らずに止まらない。
- 待ちの指示があっても、出せる成果物（push・Draft PR）は先に出す。
- done の本文には PR の URL と変更点を入れる（`note` は誰も起こさないので完了報告に使わない）。

## 3. god の `--admin` マージは PM の一言があるときだけ

- god が `--admin` でマージしてよいのは、PM がその PR について「マージまでやって」と言ったときだけ。
- 軽微に見えても、見た目・色・スクリプトの変更は、PR を見せて PM の一言を待つ。
- 起きたこと: #107 を god が自分の判断でマージし、PM に「勝手にした？」と指摘された。
- マージ後は、Pages の反映を実際の画面で確かめて報告する。

## 4. 共有の作業フォルダで、ブランチを切り替えない

- PR 用の作業は、自分の `git worktree` で行う。共有フォルダは `main` のまま触らない。終わったら `git worktree remove`（`--force` は使わない）。
- 起きたこと: 共有フォルダで誰かがブランチを切り替え、別の人の未コミットの編集が消えた（2026-11-07）。
