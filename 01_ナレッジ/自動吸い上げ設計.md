# ナレッジ自動吸い上げ＆再発防止 — 設計

## 0. 目的

開発中に出たエラー・ミスを **人が意図的に書かなくても自動で吸い上げ**、記録に残し、**二度踏まない仕組み**に変える。とくにデプロイのよくあるミスを溜め、次から避けられるようにする。既存の「手で還元する台帳」を、自動収集型へ作り替える。

## 1. 決定事項（本設計の前提）

| 項目 | 決定 |
| --- | --- |
| 収集源 | ① CI/デプロイのログ（GitHub Actions / Vercel / Render）② Claude Code の作業ログ（Bash 失敗）③ 手元のコマンド失敗 |
| タイミング | 両方＝**随時収集（イベント発生時）＋ 週1要約（定期）** |
| 適用範囲 | まず このリポジトリ単体で作る（将来の横断化は次段） |
| 予防の形 | ①デプロイ前チェックリストの自動更新 ②CLAUDE.md への「よくあるミス」自動追記 |

**なぜ両方か**: 3つの収集源はどれも「出た瞬間に発生するイベント型」。その場で拾わないとエラー全文・文脈が消え、週1では再構成になって精度が落ちる。だから「随時＝生ログを溜める」「週1＝整理して予防に昇華」の2段にする。

## 2. アーキテクチャ（2段）

```
① 随時収集（イベント発生時）
   ├ Claude Code hook (PostToolUseFailure on Bash): 失敗したら
   │    → 01_ナレッジ/_inbox/mistakes.jsonl に1行追記（マスク後）
   ├ 手元のコマンド失敗: 同じ hook 経路で捕捉
   └ CI/デプロイ失敗: Actions/Vercel/Render の失敗ステップで同 jsonl に追記
        （CI 導入後に後付け。Day1 は hook だけで動く）
                    │
                    ▼
②  週1要約（定期ルーティン：毎週月 09:00 など）
   ├ _inbox/mistakes.jsonl を読む → 重複排除 → 「ミスの型」に束ねる
   ├ 01_ナレッジ/mistakes/<型>.md に記事（原因・直し方・証拠）を追記/更新
   ├ index.md / log.md を更新
   ├【予防1】deploy-checklist.md を自動更新
   ├【予防2】CLAUDE.md の自動ブロックに「よくあるミス」を追記
   └ 処理済み行を _inbox/archive/ へ退避
```

## 3. ファイル構成（01_ナレッジ 作り替え後）

```
01_ナレッジ/
├ README.md              … 運用スキーマ（自動吸い上げ版に更新）
├ index.md / log.md      … 既存踏襲（週1 routine が自動更新）
├ 自動吸い上げ設計.md     … 本書
├ deploy-checklist.md    … ★予防1：デプロイ前の確認リスト（自動更新）
├ _inbox/
│  ├ mistakes.jsonl      … 随時の生ログ（append-only, git 管理外）
│  └ archive/            … 要約済みの退避先（git 管理外）
└ mistakes/              … 型ごとの記事（env漏れ / ビルド失敗 / デプロイ設定 …）
```

## 4. コンポーネント仕様

### 4.1 随時収集 hook（`.claude/settings.json`）
- トリガー: `PostToolUseFailure`、対象 Bash（失敗した呼び出しだけが届く。`PostToolUse` は成功時だけなので失敗を拾えない）。ユーザーの中断（`is_interrupt`）は記録しない。
- 出力の文字列（「No such file」等）では判定しない。成功したコマンドの出力を誤検知するため（2026-10-26 に5件の誤検知を確認して修正）。
- 動作: 小さな収集スクリプト（`scripts/collect-mistake.*`）を呼び、1件を `_inbox/mistakes.jsonl` に追記。
- **必ずマスクしてから書く**（§6）。
- hook はブロックしない（記録専用。作業は止めない）。

### 4.2 週1要約ルーティン（定期）
- 実行基盤: 定期実行（`/schedule` のクラウドルーティン想定。開発していない週も回り "定期自動登録" になる）。
- 手順: ①inbox 読込 → ②マスク再確認 → ③型でクラスタリング（同じ原因は1件に） → ④`mistakes/<型>.md` 追記/更新 → ⑤`index.md`/`log.md` 更新 → ⑥`deploy-checklist.md` 再生成 → ⑦CLAUDE.md 自動ブロック更新 → ⑧inbox を archive へ。
- 冪等性: 同じ型は再追加せず「発生回数・最終発生日」を更新するだけ。

### 4.3 予防1：`deploy-checklist.md`
- 週1 routine が「デプロイ系の型」から、デプロイ前に確認する項目を箇条書きで自動生成。
- 各項目に根拠（どのミスから来たか・発生回数）を併記。デプロイ着手前に読む運用。

### 4.4 予防2：CLAUDE.md の自動ブロック
- CLAUDE.md 内に機械管理の区画を設ける：
  ```
  <!-- auto:mistakes start -->
  （週1 routine がここだけ書き換える。手書き禁止）
  <!-- auto:mistakes end -->
  ```
- 再発回数が閾値（例: 2回以上）の型だけ昇格。次回 AI が作業前に必ず読む。

## 5. 生データ `mistakes.jsonl` スキーマ（1行1件）

```json
{
  "ts": "2026-10-19T12:00:00Z",
  "source": "claude-bash | shell | ci",
  "command": "<実行コマンド（マスク後）>",
  "exit_code": 1,
  "error": "<エラー全文の要点（マスク後・最大 N 文字）>",
  "context": "<何をしていたか（任意）>",
  "cwd": "<相対パス>"
}
```

## 6. 秘匿情報のマスク（必須ガード）

- エラーログには `.env` 値・トークン・接続文字列・本名が混じりうる。**収集の時点でマスクしてから書く**。無対策だと「ミス記録」が秘密漏洩源になる。
- マスク対象の例: `.env` 由来の値、`sk-`/`ghp_` 等のトークン様文字列、`postgres://user:pass@...` の資格情報、絶対パス中のユーザー名。
- 二重防御として `_inbox/`（生ログ）は **git 管理外**（`.gitignore` に追加）。コミットするのは要約済みの `mistakes/`・`deploy-checklist.md`・index/log のみ。

## 7. 段階導入

1. **Day1（CI 不要で動く）**: hook（§4.1）＋`_inbox` ＋ 週1要約の最小版＋`deploy-checklist.md`。収集源は Claude Code/コマンド失敗。
2. **CI 導入後**: Vercel/Render/Actions の失敗ステップから同 jsonl に追記（§2 の③）を後付け。
3. **予防2の昇格ルール調整**: 運用して閾値（何回で CLAUDE.md へ昇格）を見直す。

## 8. 未決・次段

- 週1 routine の実行基盤を `/schedule`（クラウド）にするか、ローカル cron にするか → 導入時に確定。
- **【決定 2026-10-19】週1要約は AI 版を主系統にする**（`weekly-digest-prompt.md` を `/schedule` に登録）。
  機械版 `scripts/weekly-digest.py` は AI を使わないときのフォールバックとして残す。
  理由: 機械版はコマンド＋エラー先頭行で束ねるため、先頭行がブレると同じ原因でも型が割れる（検証で確認）。AI 判断なら意味で束ねられる。
- 「型」の粒度（デプロイ/環境変数/DB/ビルド…のカテゴリ設計）は、最初の数件が溜まってから調整。
- 将来の複数レポ横断化（共通ナレッジ基盤）は範囲外。このリポジトリ単体で検証してから検討。

## 9. 受入の目安（この仕組みが「できた」と言える条件）

- わざとコマンドを失敗させると `_inbox/mistakes.jsonl` に1件増える（マスク済み）。
- 週1要約を手動起動すると、`mistakes/` と `deploy-checklist.md` と CLAUDE.md 自動ブロックが更新される。
- 生ログが git に乗らない（`.gitignore` 済み）。
