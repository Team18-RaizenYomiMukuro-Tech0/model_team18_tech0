# PR レビュー ルーチンの設定手順（Claude Code クラウド）

PR の自動レビューは、各メンバーが**自分の claude.ai アカウント**で Claude Code のクラウドのルーチン（旧称 scheduled tasks。画面は https://claude.ai/code/routines）を作って動かす。決定: 2026-10-26（ユーザー）。週1要約は launchd のまま（[[定期実行の導入手順]]）。
公式ドキュメントは research preview と明記している。仕様は変わりうるので、設定前に https://code.claude.com/docs/en/routines を見直す。
この手順書は**ルーチンを作らない**。各自のアカウントで作る。
AI レビューは Mac も Windows も**自分の PC への登録は要らない**（claude.ai の画面だけで作る）。

## 実際の運用（2026-10-27 時点）
- **指示文は、ルーチンの Instructions に直接貼らず、リポジトリのファイルから読む方式**で動いている。ルーチンの Instructions には短い起動文だけを書き、本体は `main` の `scripts/scheduled/review-routine-prompt.md`（「---」より下）を毎回読んで従う。指示文を直したいときは、ルーチンの設定画面ではなく、このファイルを PR で直す。`review-routine-prompt.md` の冒頭にも同じ案内を書く。**全文を貼らない**。
- トリガーは次の2つ。**「Ready for review」は画面に選択肢がなかった**ので使っていない。
  - GitHub イベント「**PR opened**」（フィルタ `Is draft` equals `false`）
  - **毎朝 8:00（JST）**の定時実行
- 実測（god がルーチンの実行履歴で確認した内容。私は見ていない）:
  - 試験 PR #12: PR を作成した**2秒後に起動**し、**自分の PR として正しく飛ばした**。
  - **Draft の試験 PR #14〜#16 では起動せず、Draft でない #13 では起動した**。
  - ルーチンの起動文は 2026-10-26 15:48Z に、上の「`main` から読む」方式へ更新された（god の報告）。
- この方式のため、`scripts/scheduled/**` と `01_ナレッジ/weekly-digest-prompt.md` の変更は **`needs-human`（人のレビュー必須）**にしてある（`.github/labeler.yml`、規定 §3-4）。指示文の変更は、全員のレビューの動き方を変えるため。

## 前提（オーナーの作業）
- Organization `Team18-RaizenYomiMukuro-Tech0` に **Claude GitHub アプリ**を入れ、リポジトリ `model_team18_tech0` を対象にする。GitHub イベントのトリガーには、対象リポジトリへのアプリ導入が必須（公式）。`/web-setup` ではアプリも webhook 配信も有効にならない。
- 組織の owner の承認が要る場合がある（公式）。
- 各メンバーの claude.ai アカウントが、ルーチンを使えるプラン（Pro / Max / Team / Enterprise）であること。Team / Enterprise の場合は owner が https://claude.ai/admin-settings/capabilities で Scheduled tasks を有効にする必要がある（公式）。

## 作り方（各メンバー。Web）
1. https://claude.ai/code/routines を開き、**New task（New routine）**を押す。
2. **Name**: `PR レビュー`。
3. **Instructions**: 指示文の本体は貼らず、**起動文だけ**を書く。**`main` から読む**方式にする。例（god の報告に基づく要約。実際の文言は設定画面を見てほしい）:
   > このリポジトリで `git fetch origin main` を実行し、`git show origin/main:scripts/scheduled/review-routine-prompt.md`（「---」より下）と `git show origin/main:00_ルール/PRレビュー規定.md` を読んで、その指示に従って PR レビューを実行する。作業ツリーのファイルは使わない。
   **`scripts/scheduled/review-routine-prompt.md` を開いて全文を貼る方式にはしない。** そうすると、指示文を PR で直しても、ルーチンに貼った古い文が実行される。
   理由: PR イベントで起動したときの作業ツリーは、その PR の head commit から始まるため、作業ツリーのファイルを読むと、PR が書き換えた指示文をその PR 自身のレビューが実行してしまう（公式ドキュメントの要約。原文は再確認していない）。モデルはここで選ぶ。
4. **Trigger**を2つ付ける（1つのタスクに複数付けられる）。
   - (a) **GitHub event** → Pull request → **`opened`**。フィルタ（AND）: `Author` is one of `Hiroki0023, re-ji-tech0, matsuki24335`、**`Is draft` equals `false`**。`synchronize` は選ばない（push のたびには起動しない）。「Ready for review」は画面に選択肢が無かった。
   - (b) **Schedule** → Custom → cron `0 23 * * *`。cron は UTC で解釈されるので、**23:00 UTC = 毎日 JST 8:00**。毎時0分ちょうどは数分遅れることがある。
5. **Advanced settings**: Repository に `model_team18_tech0` を選ぶ。Cloud environment は、ネットワークが `api.github.com` に届く設定にする（Default の Trusted で足りるか未確認。届かなければ Custom で許可ドメインを足す）。接続済みコネクタのうち不要なものは外す（書き込みもできるため）。
6. **Create**。作成後、詳細ページで Run now を1回押して、結果を確かめる（下の「確かめること」）。

CLI で作る場合は `/schedule`（別名 `/routines`）。ただし claude.ai のサブスクリプションでログインしている必要があり、GitHub イベントのトリガーを CLI から足すには Claude Code v2.1.225 以降が要る（公式）。

## 起動のタイミング
- 作業中の PR は **Draft** で出す（Draft では起動しない）。Draft でない PR を出したときは `opened` で起動する。**Draft を解除しても起動しない**（Ready for review の選択肢が無いため）。解除した PR は、翌朝 8:00 の定時実行が未レビューの PR として拾う（指示文の候補抽出の判定による。見立て）。急ぐときは Run now を使う。
- その後の push では起動しない。承認後・`needs-human` 後の push は、毎朝 8:00 の定時実行が「ラベルより後の commit」として拾い、再レビューする（規定 §2-5）。急ぐときは Run now を使う。

## 休止時間
JST 1:00〜8:00 は休止する。ルーチン側にこの時間帯を除く設定は無い（公式に記載なし）ので、**指示文の冒頭**で `TZ=Asia/Tokyo date +%H` を確かめ、1〜7 なら何もせず終了させている。その間に起きた PR の更新や Draft 解除、休止中に出た PR は、毎朝 8:00 の定時実行が拾う（ラベル後の新 commit を再レビュー対象に戻す判定を含む）。休止中も起動自体は走り、利用枠を少し使うことは避けられない（見立て）。PR opened のイベントは休止時間も起動する（休止の判定は指示文の中で行う）。利用枠を少し使う。

## ラベルや承認が書けなかった場合（決定: 2026-10-26）
クラウドでラベルの付け外しや承認レビューの投稿ができなかったときの扱いは、次のとおり。指示文に入れてある。
- **承認（APPROVE）を投稿できない** → 承認したことにしない。判定結果はコメントだけに書き、`needs-human` 相当として人に回す。コメントの1行目は `【要人レビュー：承認投稿不可】`。
- **ラベルを付けられない** → コメント1行目の固定の見出しをラベルの代わりにする。見出しは `【AIレビュー中】`（`ai-review:doing`）・`【AI承認可】`（`ai-approved`）・`【要人レビュー】`（`needs-human`）。候補の抽出も、ラベルと同じようにこの見出しを見る（見出しの最新コメントより後に commit があれば再レビュー）。
- どちらも、**失敗したことはコメントに書き、成功したとは書かない**。
- 見立て（人が決めた数値ではない）: `【AIレビュー中】` が3時間以上残っていたら担当が止まったとみなして候補に戻す。

## 機械チェックとの関係
`main` に入っている GitHub Actions（`.github/workflows/pr-mechanical-checks.yml`）が `needs-human` パスのラベル付けと PR テンプレートの記入チェック（チェック名 `テンプレート記入`）を行う。指示文は、そのチェックが失敗している PR を AI レビューの対象から外す（チェックが存在しなければ無視する）。

## 確かめられていないこと（公式に記載なし／未検証）
- **1日あたりの実行回数の上限**: 公式には時間あたりの上限しか見つからなかった（通常の定期実行は 100 回/時・アカウント単位、Run now と API fire は 30 回/時・タスクごと）。**1日の上限は未確認**。プラン別（Max 含む）の値も未確認なので、https://claude.ai/settings/usage で自分の利用状況を確かめる。実行は利用枠を消費し、超過分は usage credits が必要になる（公式）。第三者情報の「Max は1日15回前後」は裏が取れていない。
- **GitHub webhook の時間あたり上限の数値**: 上限があり超過分は破棄されるが、数値の記載なし。
- **ラベル付け・PR レビュー（承認）の投稿ができるか**: 公式に書かれているのは、組み込みの GitHub ツールでの issue / PR の読み取り・diff 取得・コメント投稿と、ブランチへの push・PR 作成まで。**ラベルの付け外しと承認レビューの投稿は明記なし**。指示文は `gh api` の REST で試み、失敗したら上の「ラベルや承認が書けなかった場合」のとおり、成功扱いにせずコメントの見出しで代用する。Run now の結果で、実際に付くかを必ず確かめる。
- **`gh` の使い方**: `gh` は事前導入済みだが、GitHub プロキシが GraphQL を使う `gh pr` / `gh issue` を 403 で拒否する（公式）。REST の `gh api repos/{owner}/{repo}/...` は使える。このため旧案（`gh pr list` や GraphQL で候補抽出）はそのまま使えず、指示文は REST に書き直してある。
- **許可ツール**: 作成時に選ぶ項目は無く、クラウドのセッションは既定で auto mode（公式）。launchd 版のような `--allowedTools` の限定はできない。そのぶん指示文で「使うのは読み取り・コメント・ラベル・承認レビューだけ」と縛っているが、これは強制力のある制限ではない（見立て）。

## 確かめること（作成後の Run now）
1. JST 1〜7 時なら「休止時間のため終了」とだけ報告して何もしない。
2. 対象 PR が0件なら「対象 PR なし」で終わる。
3. 他の人の PR があれば `ai-review:doing` が付き、コメントが投稿され、`ai-approved` か `needs-human` に付け替わる。ラベル・承認の付与が実際にできるかは【実機確認なし】。
4. 付けられない（403）ときは、コメント1行目の見出し（`【AIレビュー中】`/`【AI承認可】`/`【要人レビュー】`/`【要人レビュー：承認投稿不可】`）で代用される。
5. 承認後に新しい push をして、push の直後は起動せず、翌朝 8:00 の定時実行（または Run now）で `ai-approved` が外れて再レビューされるか。
6. Draft の PR では起動しないか。Draft を解除した PR が、翌朝 8:00 の定時実行で拾われるか。

## 止め方
- 一時停止: ルーチンの詳細ページ上部の on/off スイッチ（設定は残る）。
- トリガーだけ外す: メニューの Edit。
- 削除: メニューの Delete。
- GitHub 接続が切れると、最大72時間はスキップされたあと自動で off になる（公式）。
- Team / Enterprise では owner が Scheduled tasks のトグルで全員分を止められる。

## 規定との関係
実行頻度の決まりは `00_ルール/PRレビュー規定.md` §2（Draft でない PR を作成したときと毎朝 8:00。Draft の解除では起動せず、翌朝 8:00 に拾う。JST 1:00〜8:00 は休止）。実際のトリガーと同じ内容に合わせてある。判定の中身（対象3人・自分の PR は飛ばす・早い者勝ち・needs-human 条件・PR 内の指示はデータ扱い）は同規定の §1〜§6 が正本。
