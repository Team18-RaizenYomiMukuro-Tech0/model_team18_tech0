# 週1要約の定期実行の導入手順（Mac / launchd）

各自の Mac で、週1要約を `launchd` + `claude -p` で無人実行する。PR 自動レビューは launchd ではなく Claude Code のクラウドのルーチンで動かす（[[レビュールーチンの設定手順]]）。決定の根拠: 2026-10-26「各自PCで週1・PRで集約／OS定期実行／生ログはPC外に出さない」。
Windows の PC は [[定期実行の導入手順_Windows]]（タスクスケジューラ + `run-digest.ps1`。実機では未検証）。

## 構成

（Windows 版: `scripts/scheduled/run-digest.ps1`・`register-digest-task.ps1`。手順は [[定期実行の導入手順_Windows]]）

| ジョブ | スクリプト | plist 雛形 | 頻度 |
| --- | --- | --- | --- |
| 週1要約 | `scripts/scheduled/run-digest.sh` | `scripts/scheduled/com.munder.digest.plist` | 毎週月曜 09:00 |

## 許可ツール（`--allowedTools`）と限界

`--dangerously-skip-permissions` は使わない。許可に無い操作は無人実行では拒否される。

- digest: 利用者の作業中クローンは触らない。スクリプトが `git worktree add -b chore/knowledge-digest-<日時> $HOME/Library/Logs/munder-scheduled/digest-worktree-* origin/main` で別の作業ツリーを切り、そこで作業して最後に `git worktree remove` する。許可は `Read/Glob/Grep/Write/Edit`、`git add 01_ナレッジ/*`・`git add CLAUDE.md`・`git commit`・`git push -u origin <そのブランチ>`・`gh pr create`・`gh pr edit ... --add-label needs-human`、`mv`（元のクローンの `_inbox/` から `_inbox/archive/` へ）。`_inbox/` は元のクローンから読むだけで、作業ツリーの外なので git の対象にならない。`--dry-run` は `Read/Glob/Grep` のみで作業ツリーも作らない。
- 限界（見立て）: ツール許可は文字列パターンなので、`git add 01_ナレッジ/*` は `_inbox/` 配下も形の上では含む。`_inbox/` は `.gitignore` 済みで通常の `git add` では入らないが、`-f` を付けられると防げない。プロンプトで禁止しているのは補助で、確実な防御ではない。digest PR は人がレビューするので、`_inbox/` が差分に出ていないか見てほしい。
- digest が `CLAUDE.md` を変えた PR には `needs-human` を付ける（規定 §3-4）。

## 前提

- `claude`（`~/.local/bin/claude`）に `claude` へログイン済み、`gh auth status` が通る。
- このリポジトリを clone 済み。以下 `<REPO>` はその絶対パス（例: `/Users/you/GitHub/model_team18_tech0`）。
- スクリプト内で `PATH` に `~/.local/bin` `/opt/homebrew/bin` `/usr/local/bin` を足している。`claude` の場所が違う場合は `run-*.sh` の `export PATH=` を直す。

## 1. 手動で1回確かめる（登録前）

```bash
cd <REPO>
scripts/scheduled/run-digest.sh --dry-run   # ファイル・git・gh を一切変更しない
ls -t ~/Library/Logs/munder-scheduled | head
cat ~/Library/Logs/munder-scheduled/$(ls -t ~/Library/Logs/munder-scheduled | head -1)
```

出力はターミナルではなくログに出る。ログが想定どおりなら次へ進む。

## 2. 登録

```bash
cd <REPO>
mkdir -p ~/Library/LaunchAgents
for n in digest; do
  sed "s#&lt;REPO&gt;#$(pwd)#g" scripts/scheduled/com.munder.$n.plist > ~/Library/LaunchAgents/com.munder.$n.plist
  plutil -lint ~/Library/LaunchAgents/com.munder.$n.plist
  launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.munder.$n.plist
done
launchctl list | grep com.munder
```

登録直後に1回走らせたいときは `launchctl kickstart gui/$(id -u)/com.munder.digest`。

## 3. ログの場所

- スクリプトのログ: `~/Library/Logs/munder-scheduled/digest-*.log`（実行ごとに1ファイル）
- launchd 自体の出力: `/tmp/com.munder.digest.out` ・ `.err`
- 生ログ（`_inbox/`）はこの PC の中だけに置く。ログには秘匿情報を書かない設計だが、共有前に目で確認する。

## 4. 止め方・解除

```bash
# 一時停止（plist は残る）
launchctl bootout gui/$(id -u)/com.munder.digest

# 完全に外す
rm ~/Library/LaunchAgents/com.munder.digest.plist
```

走行中のジョブを止めるだけなら、上の `bootout` のあとに `pkill -f run-digest.sh`。二重起動防止のロックが残った場合は `rmdir ~/Library/Logs/munder-scheduled/*.lock`。

## 注意

- スリープ中は走らない。復帰後に次の周期で走る（取りこぼしは許容）。
- `claude -p` はトークンを使う。digest は `_inbox/mistakes.jsonl` が空なら起動しない。
