# 作業フォルダの強制削除で、未コミットの記録が消える

- 発生回数: 1（2026-11-13、B6 #64 の作業。手で記録した型。Issue #219）
- 収集源: 手書きの還元（自動収集の対象外。Bash は失敗していない）
- デプロイ系: いいえ

## 症状・実行コマンド

- `git worktree remove --force <作業フォルダ>` を実行したら、`db_admin.py` が作業フォルダに書いた未コミットの記録 `evidence/db/2026-11-13_3.md` が一緒に消えた。
- コマンドは成功し、エラーは出ない。消えたことに気づくのは後になる。
- 記録は作り直した（PR #218）。

## 原因

- `db_admin.py` は記録を、動かした場所の `evidence/db/` に書く。git worktree の中で動かすと、作業フォルダ側に書かれる。
- 記録はコミット前だった。`--force` は未コミットのファイルがあっても削除するので、フォルダごと消えた。
- 「証拠なき完了報告の禁止」（作業ルール）の証拠そのものが、後片付けで消える形になっていた。

## 直し方 / 再発防止

Issue #219 の PM 決定（2026-11-13「Aで」）。

1. 記録の保存先を本体のフォルダに固定する（#1）。`git rev-parse --git-common-dir` の親の `02_プロジェクト/giftia-ui-renewal/evidence/db/`。作業フォルダの中から動かしても本体に残り、最後に「コミットしていない記録: <パス>」を出す。
2. 未コミットのファイルがある作業フォルダの `git worktree remove --force` を、Claude Code の hook で止める（#2）。未コミットがあるときだけ exit 2 で止め、ファイル名を出す。判定できないときは通す。
3. 手で守ること: 作業フォルダを消す前に `git status` を見る。出た記録や証拠は先にコミットして push するか、本体へ移す。`--force` は未コミットが無いと確かめてから使う。
