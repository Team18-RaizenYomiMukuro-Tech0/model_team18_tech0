# 担当の作業フォルダに自動で作られたファイルが残り、依頼が「未コミットの変更」で止まる

- 発生回数: 1（2026-11-20 13:00 ごろ。Mi-rin の `fix-240-front-mirin`）
- 収集源: りじちょーの assign の返事、`git status --short`
- デプロイ系: いいえ

## 症状

りじちょーが Mi-rin に #240 の続き（注記 2 件に理由を足す）を assign すると、アプリが「待機中です（理由：未コミットの変更）」と返した。`team_status` では Mi-rin は FREE だった。依頼は渡らず、止まったままになった。

## 原因

担当の作業フォルダに、未追跡の `frontend/AGENTS.md`（9 行）が残っていた。Next.js が開発サーバーやビルドの起動時に自動で作る「AI 向けの案内」で、11:34 にできていた。担当が作ったファイルではない。`.gitignore` に入っていないため、アプリは「未コミットの変更がある」と見て、作業フォルダを使い回さなかった。

## 直し方 / 再発防止

- その場の直し: りじちょーが中身を見て、自動で作られたものと確かめてから消した。そのあと assign を出し直して渡った。
- 仕組み: `frontend/.gitignore` に `AGENTS.md` を足した（同じ PR）。以後は未追跡として数えられない。
- 運用: assign が「未コミットの変更」で待機になったら、`git -C <作業フォルダ> status --short` で中身を見る。担当の作業の途中なら消さず、担当に「コミットするか捨てるか」を聞く。自動で作られたものなら `.gitignore` に足す。
