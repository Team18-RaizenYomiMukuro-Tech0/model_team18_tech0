# 11/25 の実運用のセキュリティのレビューの学び 6 つ

根拠: 11/25 の実運用のセキュリティのレビュー（AI チームの運用が対象。PM 依頼「ナレッジもシェアできるようにまとめておいて」）。関連 PR: #725・#726・#700。このリポジトリは公開なので、個人名・メールアドレス・個人のパス・Azure や DB の接続先・秘密の値は、この記事に書いていない。

「決まり」と「案」を分けて書く。案は、PM がまだ採っていない。

## 1. 公開のリポジトリでは、AI の書く PR・コメント・証拠が、そのまま外に出る

- 起きたこと: Windows 機の週1要約（#700）の PR 本文（Windows 機側の AI が書いた）に、実行ログ由来のパスが入り、そこに Windows のユーザー名が含まれていた。りじちょーがそれを写したコメントにも、同じ名前が出た。伏せたのは、りじちょーのコメントだけ。#700 の本文には残っている（本人の文なので直していない）。見つけたのは、レビューで公開ページの目でログを読み直したとき。
- 学び: PR 本文・コメント・証拠のコマンド出力は、書いた時点で世界中に見える。名前・個人のパス・URL は、写す前に見る。写すなら、伏せ字にする。
- 決まり: 既に `作業ルール.md` に「秘匿情報を残さない」がある。パス・ユーザー名・画面の写しまで含める明文化は、案（未決）。

## 2. 禁止の設定は、道具ごとにしか効かない

- 起きたこと: `.env` を Read ツールで開くことは禁じていた。しかしシェルの `cat`・`head`・`tail`・`less` で同じ `.env` を開けた。別の道具で試して分かった。#726 で `.claude/settings.json` の deny に、この 4 つで `.env` を開く形を足した。
- 学び: 止めたつもりの所は、別の道具で試して確かめる。Read・Bash・エディタ・スクリプトは、それぞれ別の入口になる。
- 残ること: deny に書いた形以外で開く道が残るかは、確認していない。

## 3. `.git/info/exclude` はその機だけ。`.gitignore` は全員に効く

- 起きたこと: Daasa Muffin の作業フォルダ（記憶ファイル・貼った画像・会話の記録・担当の作業フォルダ）は、PM の Mac の `.git/info/exclude` だけで外していた。ほかの機で `git add -A` をすると、公開のリポジトリに載るおそれがあった。#726 で `.gitignore` に `.command-center/` と `command-center.json` を足した。
- 学び: 代表機を交代で使うチームでは、全員に効く `.gitignore` に置く。`.git/info/exclude` は、その機の個人用に限る。
- 確認: 今までに git に入った物は 0 件（#726 の証拠）。

## 4. 誰でも呼べる書き込みの API は、回数と本文の大きさの上限を、設計のうちに決める

- 起きたこと: 上限（本文の大きさ）を設計で決めていた API は、守れていた。一部の書き込みの API には上限が無い。レビューで、書き込みの API を 1 本ずつ見て分かった。
- 学び: 認証が無い書き込みは、誰でも何度でも呼べる。回数と本文の大きさは、実装の後で足すのでなく、設計の段で書く。
- 決まっていないこと: 上限の無い API の、回数の制限と本文の上限は、PM が今回選ばなかった。決まっていない。ほかの指摘の直しも同じで、決まっていない。

## 5. AI は PM の GitHub アカウント（管理者）で動く。AI の権限は PM と同じ大きさになる

- 起きたこと: レビューで、AI が使う認証が PM のアカウントで、管理者の権限を持つと分かった。止めているのが運用だけの操作がある（main へのマージは、入力欄に PM が「承認します」と打つ。`main へのマージの承認は入力欄に打つ.md`）。
- 学び: 技術で止められない所は、運用で止めている。その運用を、決まりとして書いておく。
- 案（未決）: 止め役が入力欄の「承認します」だけの操作を洗い出し、決まりに書く。AI 用の権限の小さい認証を使う案もあるが、アカウントや設定の変更になるので、運営への相談が先。

## 6. ディスクが満杯になると、AI は何もできなくなる

- 起きたこと: 11/25、担当の作業フォルダ 23 個で 4.9GB になり、ディスクの空きが 124MB になった。コミットもコマンドも止まった。 PM がディスクを空けた後、終わった作業フォルダ 12 個（PR がマージ済みか閉じ済みの 7 個、PR 無しで終わった 5 個）を消し、約 3.5GB 空いた。消す前に、未集計のミスの記録 5 件を main の `_inbox` へ移した。空きは 13GB になった。
- 学び: 作業フォルダ（worktree）は、案件が終わったら消す。消す前に、未コミットの記録が無いか見る（`mistakes/worktree-force-remove-loses-uncommitted.md`）。
- 案（未決）: 空きが少なくなったら知らせる確認と、終わった作業フォルダを片づける手順。
