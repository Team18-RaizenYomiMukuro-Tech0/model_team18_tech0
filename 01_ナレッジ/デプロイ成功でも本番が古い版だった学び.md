# デプロイ「成功」でも本番が古い版だった学び

2026-11-14。PM「いい学びだね」。出典: PR #262 の本文とレビューコメント。

## 1. 症状
- GitHub Actions も Azure も成功・Active なのに、本番の画面が 11/13 夕方の版のまま、約1日残った。
- りゅうちゃんが #135（公開後の実機確認）で見つけた。

## 2. 原因（確度は高い。Azure 側の中身は見ていない）
- zip デプロイは、置き場所の古いファイルを消さない。
- zip からは `.next/cache` を除外している。Azure に残っていた古い作り置きページ（`/search`。応答ヘッダー `x-nextjs-cache: HIT`、ETag が6回とも同じ）が、新しい版を隠した。
- 確かめたこと: 送った zip の新しい JS は本番でも取れる（200）のに、`/search` は古い JS を読んでいた。

## 3. 直し
- PR #262: デプロイの設定に `clean: true`（置く前に置き場所を空にする）を1行足した。マージ済み。
- **効果は確認中**（god がマージ後に確認。`/search?scene=送別` に「選んだ候補」が出る、ETag が変わる）。`clean` が zip デプロイでも効くかの根拠は、公式 `action.yml` の説明だけ。確定したら追記する。効かなかったときは、再起動・`.next/cache` の扱いを PM 判断で検討する。

## 4. 抜け（防ぎ方）
- デプロイの成功で止め、**本番の版を誰も確かめていなかった**。
- りじちょーも最初「新しい版が入っている」と誤報した。以前からある文字列で判定したため。
- 守ること:
  - デプロイのあとは、**今回の変更で初めて出る文字・要素**（新しい版にしか無いもの）が本番に出るかを見る。「成功」の表示では判定しない。
  - 見るものを決めて PR に書く（例: 画面の文言、ETag や応答ヘッダーが変わったか）。
  - 判定に使う文字列は、以前からあるものを避ける。

## 5. 本物の EC との違い
- 今回のやり方は、置き直しの間（1〜2分）画面が止まる。
- 本番の運用では、デプロイスロットに新しい版を置いて Swap（入れ替え）すれば止まらない。ただし B1 プランではスロットが使えない。上げるなら運営に相談する。
- 評価・発表の直前は、マージしない（デプロイが走り、止まるため）。
