# ハブの見た目の決まり（押せる形・STAGE 表示・早見表）

開発ハブ・全体像・セットアップ・進捗ダッシュボードの画面の決まり。2026-11-06〜11-07 に PM が決めた。決定の記録は `log.md`。

## 1. 押せる所の形は3つだけ

押せる所と押せない所を、見た目で見分けられるようにする。他の形は使わない（PR #108・#110。PM「オッケー」、2026-11-07）。

| 種類 | 形 | 使いどころ |
| --- | --- | --- |
| ボタン | 濃い塗りの丸い札＋→（「開く →」など） | 画面の移動（進捗ダッシュボードには該当する操作が無く、新設していない） |
| リンク | 下線。外のサイトには ↗ も。マウスを乗せたとき・キーボードで選んだとき（hover / focus-visible）に下線を太くする | 文中・一覧の中の移動 |
| 状態（押せない） | 枠なしの薄い塗りの札 | 「未着手」「完了」「レビュー待ち」「遅延」「準備中」「予定」「動いている」など |

- 点線の枠・太い枠で囲んだ状態の札は使わない。
- 遅延のように目立たせたい状態も、濃い塗り（ボタンに見える）にせず、薄い塗りで色を変える。
- 名前の絞り込みや並べ替えは「移動」ではなく表示の切り替えなので、PR #108 では触っていない。

## 2. STAGE 4 の表示

案の選び: 色は比較ページの A「黒い札に3色のふち」、門は案3「進み具合で開く」。PM「AとBで」（#107）、のち「案3で」（#109）。2026-11-07。

- STAGE 4 の札は濃い紺（`#2A1B3D`）の地に 黄→青緑→桃 の3色のふち、白文字。文字のグラデーション塗りはしない。「いま」のときは外に白い輪。
- ゲージ右端は、元の「門」。ゲージの「全体 ○%」と同じ値で扉が開く（0% で閉じ、100% で左右いっぱい）。すぐ下に「発表 11/24」（日付は手書き。`progress-summary.json` に発表日が無いため）。光はゆっくり、`prefers-reduced-motion` では止める。
- STAGE 1〜3 は軽くする: 札は枠なし・その段の色の薄い塗り、バーは細く（8px）薄い紫の地。STAGE 4 だけ目立たせる。
- 新しい色は作らない（既存の m1・m2・m3 と紺）。原作の絵・ロゴは使わない。
- 色はハブのゲージ（`docs/hub-assets/band.css`）と進捗ダッシュボード（`scripts/build-progress.py`）で同じ値にし、`scripts/test_build_progress.py` が突き合わせる。

## 3. 全体像の早見表と段階カード

PR #101〜#105（PM「オッケー」ほか、2026-11-07）。

- Issue の早見表は手書きをやめ、`scripts/build-progress.py` が書き出す `issues-quick.json`（`progress-summary.json` の隣）から表示する（#102・#103）。読めないときは進捗ダッシュボードへのリンクだけを出す。
- 段階カードの「くわしく」は、P/B/F/T の分野ごとに「できる状態」を1行ずつ（#103）。文の根拠は各 Issue の「完成すると何ができる？」。
- PM（P）の行は、実装①・実装②の段階カードの「できる状態」から外す（#105。#104 は同じ内容で閉じ、#105 に統合）。早見表の中の P の Issue はそのまま。
